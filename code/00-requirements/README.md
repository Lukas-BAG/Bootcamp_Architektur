# Übung 00 — Vom Problem zum Plan

Diese Übung ist bewusst **kein Java-Code** — Anforderungen und Architekturentscheidungen schreibt man zuerst in Prosa, nicht in Klassen. Bearbeite die beiden Vorlagen für ein selbst gewähltes, kleines Szenario (z. B. eine App zur Verwaltung einer WG-Einkaufsliste, ein kleines Vereins-Tool, ein Buchungssystem für einen Proberaum — irgendetwas, das du dir konkret vorstellen kannst).

## Aufgabe 1 — `User_Stories_Vorlage.md`

Schreibe **mindestens zwei** User Stories für dein Szenario, jeweils inklusive Akzeptanzkriterien im Given-When-Then-Format. Orientiere dich am Beispiel in Modul 00, Kapitel 2.

## Aufgabe 2 — `ADR_Vorlage.md`

Triff eine echte, kleine Architekturentscheidung für dein Szenario (z. B. "Datenbank X statt Y", "REST statt GraphQL", "Monolith statt Microservices für den Start") und dokumentiere sie als vollständiges ADR — inklusive mindestens einer ehrlichen **negativen** Konsequenz. Ein ADR ohne Nachteile ist kein ADR, sondern Werbung für die eigene Entscheidung.

## Selbstkontrolle

Frag dich bei beiden Dokumenten:
- Könnte eine neue Person im Team allein aus meiner User Story verstehen, *warum* sie existiert (nicht nur *was* sie tut)?
- Könnte eine neue Person im Team aus meinem ADR verstehen, unter welchen Umständen die Entscheidung überdacht werden müsste?

Wenn ja — bist du bereit für Modul 01.
